# 侧幅透视艺术字方案（SIDE ART · ✅ 已按审核批准实施：B + RANKING + 含网格 + 克制闪烁 + 1400px）

> 需求原文：左侧 "GitHub"、右侧 "ranking list" 艺术字，向中心透视、四周大中间小，像素风字体、黑客复古风配色；欢迎更优方案；**文档审核通过后再实施**。
> 场景：宽屏（≥1400px）下终端两侧的黑色空区。窄屏无此空区，功能不受影响。

---

## 一、需求解读（先对齐认知）

「向中心透视，四周大中间小」= 以屏幕中心（终端）为透视灭点：**字母竖排成列，字号从垂直中心向上下两端递增**（中间的字母最小、两端最大），同时整列绕 Y 轴向中心倾斜（左列右倾、右列左倾，字面朝向终端）——模拟广角镜头下"中心是实体、四周被拉伸放大"的效果。

## 二、方案对比

### 方案 A · 按原文直做：像素字体 + CSS 3D 透视

Press Start 2P 等像素字体，transform: perspective() rotateY() 硬透视。
- ❌ 需要下载字体文件（本机代理是死端口，curl --noproxy 可试但不可靠）
- ❌ 3D 透视大字在暗底上容易显得"贴上去的"，与终端血统不搭
- ❌ 引入二进制字体资产，违背项目"零依赖"优点（CSP 本身无碍）

### 方案 B · 像素点阵字母竖幅（★ 推荐）

每个字母用 **5×5 点阵字符画**（█ 与空格拼出，数据驱动），现有等宽字体渲染——**零新依赖、零网络请求、CSP 天然友好**。块字符本身就是终端原生的"像素"，血统纯正。

- 竖排：G·I·T·H·U·B 从上到下堆叠成左幅；R·A·N·K·I·N·G（或全称）成右幅
- 「中间小四周大」：字号梯度 0.85em → 1.15em → 1.55em 三档对称（列中间最小、两端最大）
- 「向中心透视」：容器 perspective: 900px，左幅 rotateY(14deg)、右幅 rotateY(-14deg)（字面朝向终端）
- 配色：主体 --dim 级暗绿，随机 2-3 个字母提亮为 --ink + 辉光——像一列老霓虹灯箱，个别灯管更亮
- 生命感：每字母独立 flicker 动画（随机 delay 的透明度抖动，坏灯管效果）；prefers-reduced-motion 全局开关下自动静止 ✓
- 成本：约 120 行 CSS + 一段点阵数据 + 少量 HTML，纯静态无 JS

### 方案 C · 氛围增强（可选叠加，默认开）

两侧空白加**极暗透视网格地平线**（synthwave grid，透明度 3-6%，纯 CSS 渐变，零元素）——与"向中心透视"呼应，让大字"立"在地面上而不是浮在虚空。可独立开关。

**推荐：B 为主体，C 作为可选项一并实现（各约 30 行 CSS，不喜欢随时关）。**

## 四、技术要点

1. **零布局风险**：fixed 悬浮两侧空区，不触碰 .term 文档流，窄屏直接隐藏。
2. **零依赖**：点阵字母纯 HTML+CSS 静态拼装，无 JS、无字体文件、无网络请求。
3. **CSP 合规**：无外链、无内联样式/脚本，全部进 style.css / index.html。
4. **RM 安全**：闪烁动画自动被全局 reduced-motion 规则杀掉，静态显示。
5. **性能**：两侧各约 10 个字符节点 + 1 个网格背景，开销可忽略。

## 五、验收清单

1. ≥1400px 宽屏两侧出现竖幅；<1400px 完全消失；终端区域布局零变化
2. 字号梯度肉眼可辨（中间小两端大）；两幅字面朝向终端（rotateY 方向正确）
3. 闪烁存在但克制；RM 下完全静止
4. 文档无滚动条（溢出探针 offenders 为空）
5. node --test 31 条全绿；截图人工审核整体气质

## 六、明确不做

- ❌ 字符雨/矩阵雨——太闹，抢内容
- ❌ 3D 旋转常驻动画——透视角度静态即可，动起来晕
- ❌ 外链字体/图片——CSP 与零依赖原则
- ❌ 两侧放可交互元素——纯装饰
